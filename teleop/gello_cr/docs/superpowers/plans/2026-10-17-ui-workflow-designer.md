# Qt Designer 与采集工作流优化实施计划

> 执行方式：沿用已完成的 P0 审计，按互不重叠的文件范围并行实施，主代理集成、验证与最终审查。用户已要求推进修改，不在每一阶段重复请求确认。

**目标：** 修正已确认的连接、HOME、断流和许可问题，让主要布局由 Designer 维护，统一持续状态和采集交互，同时保留现有驱动、仲裁与 Dataset 后端。

**依据：** [P0 审计](../../ui_ux_architecture_audit.md)。软件保持 PySide6，不改训练、Policy 推理或厂商底层驱动，不增加虚假机器人实现或凭空限位。

## 实施任务

- [x] 连接与许可：区分主动下使能/断开和异常故障；HOME 要求明确使能、非遥操/REC/FAULT/ESTOP；统一 Pending 与保存许可；保留安全命令抢占。
- [x] 相机与采集：运行中必要图像持续过期后停止采样并留 Pending；显示真实质量/丢样指标；减少 GUI 快照复制/锁内 I/O。
- [x] Designer：迁移主壳、采集和其他主要页面布局到 `.ui`，生成代码禁止手改；唯一 objectName 与语义属性分离；QSS 外置与包资源。
- [x] 通用设备视图：增加真实 CR3A 描述与能力接口，Robot/Servo/输入设备/Teleop/REC/FPS/Dataset/Episode/Fault 持续可见；不按机器人复制页面。
- [x] 采集 Controller：单一 Presenter poll，分发同一 UiFrame；收拢步骤、表单、保存回执和风险确认；明确 Start/Finish/Discard，录制冻结切换。
- [x] 完善数据集/错误：新建、恢复未完成、只读已发布的语义清楚；错误有来源、持续可见；保留恢复/合并与关闭策略。
- [x] 清理与交付：删除被替代的手写静态布局和旧源字符串断言，更新操作文档；功能回归、静态检查、真实离线渲染与独立审查。

## 验证与边界

安全和数据行为用少量对应回归覆盖真实应用链；先确认回归可捕获缺陷再修复。布局主要复用现有 Qt 交互测试并实际渲染，不增加哈希、像素匹配、冒烟框架或无意义测试层。完成后运行项目离线套件；官方 V2.1/V3 环境沿用现有 `/tmp` 解释器。
